# Скрипт лимитов Codex: требования

> Это техническое задание, по которому автор написал свой `codex_usage.py`; сам скрипт в этот
> репозиторий не входит. Пути `E:\Development\AI\...` ниже — с машины автора. Для своего скрипта
> важен контракт: `--json`, `schema: 1`, коды выхода и чистый stdout (разделы ниже). Путь к нему
> задаётся в `TASK_DELEGATOR_CODEX_USAGE_SCRIPT`.

## Зачем

Нужен один скрипт, который читает текущие лимиты Codex для аккаунта, залогиненного на этом ПК.
Им пользуются два потребителя:

1. **Хук Codex.** После каждого ответа показывает пользователю строку с лимитами.
2. **MCP-сервер `task-delegator`** (Claude, `E:\Development\AI\Claude\Projects\MCP\TaskDelegator`). Перед тем как
   ставить Codex задачу, он проверяет, хватит ли лимитов; после задачи показывает, сколько она
   стоила. Скрипт вызывается подпроцессом с `--json`, поэтому JSON-контракт, коды выхода и
   «чистый» stdout — это публичный интерфейс. Менять его можно только с повышением `schema`.

Текущая Node-версия (`codex-usage-mcp.js`) по идее верна, и её источник данных сохраняется.
Но на этом ПК она не запускается без ручных путей (`node` и `codex` нет в PATH), а её Stop-хуки
тратят лишний ход модели на каждый ответ. Новая версия заменяет её.

## Источник данных

Тот же, что в Node-версии: запустить `codex app-server --stdio` и обменяться JSON-RPC
сообщениями (по одному JSON на строку):

1. запрос `initialize` (`clientInfo`: имя `codex-usage`);
2. уведомление `initialized`;
3. запрос `account/rateLimits/read`, ответ на него и есть данные.

Требования к запуску процесса:

- без консольного окна (`CREATE_NO_WINDOW`), без `shell=True`, без запуска через `cmd.exe`;
- таймаут по умолчанию 20 с, меняется через `--timeout`;
- **дочерний `app-server` должен завершаться на любом пути выхода**: успех, ошибка, таймаут,
  исключение, Ctrl+C. Осиротевших процессов `codex.exe` оставаться не должно;
- stdout `app-server` читать как UTF-8 построчно. Строки без `id`, уведомления и строки, которые
  не разбираются как JSON, пропускать. Ответ с `error` превращать в понятную ошибку;
- скрипт только читает. Он не трогает `~/.codex/auth.json`, не хранит и не выводит токены,
  не открывает сетевых портов и ничего не пишет на диск.

## Поиск `codex.exe`

Порядок:

1. аргумент `--codex-exe PATH`;
2. переменная окружения `CODEX_USAGE_CODEX_BIN`;
3. `%LOCALAPPDATA%\OpenAI\Codex\bin\*\codex.exe`. Брать самый свежий по времени изменения:
   папка с хешем меняется при каждом обновлении Codex, поэтому путь нельзя зашивать;
4. `codex.exe` из PATH, но только настоящий `.exe`. Если в PATH лежит обёртка `codex.cmd` или
   `codex.ps1` (так бывает после установки через npm), искать рядом
   `node_modules\@openai\codex\vendor\*\codex\codex.exe`. Если не нашёлся, выдать понятную ошибку.

## Python API

```python
from codex_usage import read_usage, CodexUsageError

usage: dict = read_usage(codex_exe: str | None = None, timeout: float = 20.0)
```

- Возвращает ровно ту структуру, что печатает `--json` (см. ниже).
- При любой неудаче бросает `CodexUsageError` с коротким читаемым сообщением.
  Не возвращать нули вместо отсутствующих данных.

## Командная строка

```text
python codex_usage.py                    # одна строка текста для человека
python codex_usage.py --json             # JSON-контракт
python codex_usage.py --hook codex-stop  # вывод для Stop-хука Codex
python codex_usage.py --hook claude-stop # вывод для Stop-хука Claude Code
  общие опции: --codex-exe PATH  --timeout SEC
```

Коды выхода (для режимов без `--hook`):

| Код | Когда |
|---|---|
| `0` | данные получены |
| `1` | данные недоступны: ошибка запуска, таймаут, ошибка `app-server`, нет входа. Одна строка с причиной идёт в stderr |
| `2` | неверные аргументы |

**В stdout — только результат**, то есть JSON или строка текста. Вся диагностика идёт в stderr.

### Текстовый формат

Одна строка в том же стиле, что у сторожа лимитов Claude: показывается **израсходованный**
процент и локальное время сброса.

```text
Codex limits: 5h: 45.0%, R: 2026-11-17 05:22 · 7d: 7.0%, R: 2026-11-23 19:13
```

- Если ведёр (`buckets`) несколько, перед каждым ставится его имя.
- Если `ordinary_usage_allowed == false` или лимит достигнут, в конец добавляется ` · LIMIT REACHED`.

### Режимы хуков

- Входной JSON хука читать из stdin. Он может быть пустым, а stdin может быть вообще не
  перенаправлен: скрипт не должен на этом зависать.
- Ответ — один JSON-объект с полем `systemMessage`, где лежит текстовый формат выше.
  Пользователь увидит цифры, а **лишнего хода модели не будет**. Не использовать
  `decision: "block"`, продолжение хода и `additionalContext` с просьбой «дописать футер».
- При ошибке: `{"systemMessage": "Codex limits unavailable: <причина>"}`.
- **Код выхода в режимах хуков всегда `0`**: сбой отчёта не должен ломать ход хоста.
- `claude-stop`: `systemMessage` в Stop-хуке Claude Code показывается пользователю. Это уже
  проверено на стороже лимитов Claude.
- `codex-stop`: **проверить по документации или схеме хуков Codex**, что Stop-хук Codex
  принимает `systemMessage` и показывает его пользователю. Если нет, выбрать формат, который
  показывает текст **без** дополнительного хода модели, и описать в отчёте, на чём основан выбор.

## JSON-контракт (`--json` и `read_usage()`)

```json
{
  "schema": 1,
  "measured_at": "2026-11-17T01:20:05+02:00",
  "source": "codex app-server account/rateLimits/read",
  "codex_exe": "C:\\Users\\...\\OpenAI\\Codex\\bin\\<hash>\\codex.exe",
  "plan_type": "plus",
  "ordinary_usage_allowed": true,
  "reset_credits_available": 3,
  "buckets": [
    {
      "id": "codex",
      "name": "codex",
      "limit_reached": null,
      "windows": [
        {
          "kind": "primary",
          "label": "5h",
          "window_minutes": 300,
          "used_percent": 45.0,
          "remaining_percent": 55.0,
          "resets_at": "2026-11-17T05:22:28+02:00",
          "resets_at_unix": 1794885748,
          "resets_in_sec": 14543
        },
        {
          "kind": "secondary",
          "label": "7d",
          "window_minutes": 10080,
          "used_percent": 7.0,
          "remaining_percent": 93.0,
          "resets_at": "2026-11-23T19:12:59+02:00",
          "resets_at_unix": 1795453979,
          "resets_in_sec": 582774
        }
      ]
    }
  ]
}
```

Правила:

- **Никаких идентификаторов аккаунта, email и токенов** в выводе.
- Неизвестное значение пишется как `null`, а не `0`.
- Проценты обрезаются в диапазон 0–100 и выводятся как числа с плавающей точкой.
- Время пишется в локальном часовом поясе в ISO 8601 со смещением. Рядом дублируется unix-время
  и число секунд до сброса (не меньше 0).
- `label` вычисляется из `window_minutes`: 300 → `5h`, 10080 → `7d`, остальное в том же стиле
  (`90m`, `1d`, `2d 4h`).
- Если есть `rateLimitsByLimitId`, сохранять все ведра. Если его нет, использовать `rateLimits`
  как единственное ведро.
- Поле `limit_reached` берётся из `rateLimitReachedType` (или `null`).
- `schema` повышается только при несовместимом изменении контракта.

## Тесты

`unittest` из стандартной библиотеки. Запуск:

```powershell
& "E:\Development\AI\Claude\Utils\Bin\Windows\Python3\python.exe" -m unittest test_codex_usage.py -v
```

Офлайн, без настоящего Codex, должны покрываться:

- **нормализация** на сохранённом образце ответа `account/rateLimits/read`: ведро `codex`,
  окна 300 и 10080 минут. Образец обезличить, без id аккаунта;
- **неполные данные:** нет окон, нет `resetsAt`, проценты вне 0–100, несколько вёдер,
  только `rateLimits` без `rateLimitsByLimitId`;
- **вывод:** текстовый формат и вывод обоих режимов хуков, включая вывод при ошибке;
- **поддельный `app-server`:** маленький Python-скрипт вместо `codex.exe`. Нужны сценарии:
  нормальный ответ; ответ с `error`; процесс сразу завершается; процесс молчит → таймаут.
  После таймаута дочерний процесс должен быть мёртв;
- **поиск exe:** приоритет `--codex-exe` и `CODEX_USAGE_CODEX_BIN`, выбор самой свежей папки
  в `%LOCALAPPDATA%`, отказ от `.cmd`-обёртки и находка вендорного `codex.exe` от npm;
- **коды выхода** CLI: 0, 1 и 2.

Плюс один живой запуск `--json` на этой машине. Его результат приложить к отчёту.

## Не делать

- Своего MCP-сервера в скрипте не нужно: MCP-сервер у нас один, это `task-delegator`, и он вызывает
  скрипт сам.
- Не менять автоматически `~/.codex/hooks.json`, `~/.claude/settings.json` и любые другие конфиги.
  В README только привести готовые фрагменты с абсолютными путями к `python.exe` и скрипту.
- Не трогать проект `E:\Development\AI\Claude\Projects\MCP\TaskDelegator`.
- Не кэшировать результаты на диск.
