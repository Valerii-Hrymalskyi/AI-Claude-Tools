# UsageGuard — лимиты Claude под контролем

`usage_guard.py` следит за расходом 5-часового и 7-дневного окна подписки Claude и
сообщает его прямо в сессию Claude Code: ассистент видит бюджет на каждом
сообщении, а вы — итог после каждого хода. Когда окно почти израсходовано,
ассистент не упирается в 429 посреди мысли, а встаёт на паузу по протоколу
навыка `long-run` и сам продолжает после сброса.

Инструмент принадлежит **машине и аккаунту Claude**, а не какому-либо проекту:
хуки прописаны на уровне пользователя и работают в любом каталоге. На одной
машине может быть несколько аккаунтов (например, головной `~/.claude` и другие в
`~/.claude-accounts/<имя>`); каждый видит **свои** лимиты.

Как устроены лимиты, откуда берутся цифры и почему им можно верить —
[`usage-limits.md`](usage-limits.md).

---

## Состав папки

| Файл | Что это |
|---|---|
| `usage_guard.py` | сам guard: хуки, ручные проверки, ожидание сброса |
| `install_user_hooks.py` | подключает guard ко всем аккаунтам на машине одной командой |
| `skills/long-run/SKILL.md` | навык Claude Code: протокол паузы и возобновления |
| `verify_usage_guard.py` | самотест — гонять после любой правки `usage_guard.py` |
| `calibrate_usage_estimate.py` | ручная перекалибровка оценки по стенограммам (нужна редко) |
| `usage-limits.md` | справочник: окна, источники данных, калибровка, история решений |

Python — общий портативный для инструментов этого репозитория (ставится
`python_setup.bat` в корне клона):

```
<clone>\Utils\Bin\Windows\Python3\python.exe
```

Ниже он сокращённо `<python>`, а путь к этой папке — `<guard>`
(`<clone>\Projects\UsageGuard`), где `<clone>` — папка клона. Сторонних пакетов guard не
требует, только стандартная библиотека.

---

## Быстрый старт

1. [Выпустить токен](#1-выпустить-токен) для каждого аккаунта — под этим аккаунтом.
2. [Положить его](#2-положить-токен) в `<каталог аккаунта>\usage-limits-token`.
3. [Подключить хуки](#3-подключить-хуки-и-навык): `<python> <guard>\install_user_hooks.py`.
4. Перезапустить Claude (приложение или сессии CLI).
5. [Проверить](#4-проверить): `<python> <guard>\usage_guard.py -mode probe` и `-mode status`.

Токен **необязателен**: без него guard работает на локальных файлах, но менее
точно (см. [«Откуда цифры»](#откуда-цифры)).

## 1. Выпустить токен

Токен — долгоживущий OAuth-токен `sk-ant-oat01-…` (около 108 символов) от
`claude setup-token`. Он привязан к **тому аккаунту, под которым выпущен**, и
показывает лимиты именно этой подписки.

### Найти `claude.exe`

Отдельной установки `claude` в PATH обычно нет — CLI лежит внутри десктопного
приложения. Обычный PowerShell, **не от администратора**:

```powershell
$pattern = Join-Path $env:LOCALAPPDATA "Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\claude.exe"
Get-ChildItem $pattern -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1 -ExpandProperty FullName
```

**Грабли.** Приложение поставлено как MSIX-пакет, и каталог под `%APPDATA%`
внутри него **виртуализованный**: он существует только для процессов самого
приложения. Обычный PowerShell путь через `%APPDATA%` не видит («имя не
распознано»), даже когда тот выглядит правильным. Настоящий путь — под
`LocalCache`, его и выдаёт команда выше.

Другие варианты установки:

```powershell
(Get-Command claude -ErrorAction SilentlyContinue).Source                       # npm / в PATH
Get-ChildItem "$env:LOCALAPPDATA\Claude-Data\claude_*\claude-code\*\*\claude.exe" |
  Sort-Object LastWriteTime | Select-Object -Last 1 -ExpandProperty FullName    # бандл приложения
```

### Выпустить

**В своём терминале**, не из сессии ассистента: команда ждёт подтверждения
входа в браузере и в неинтерактивном запуске просто зависнет.

```powershell
& "<путь-к-claude.exe>" setup-token
```

Чей это будет токен, решает **вход в браузере**: подтверждайте учёткой того
аккаунта, для которого выпускаете токен. Для второго аккаунта запустите команду
ещё раз и войдите в браузере его учёткой (если браузер сам подставит первую —
выйдите или используйте приватное окно). Токен, выпущенный не той учёткой,
покажет чужие лимиты.

## 2. Положить токен

Guard ищет токен в файле каталога **своего** аккаунта:

```
<каталог аккаунта>\usage-limits-token
```

где `<каталог аккаунта>` — значение `CLAUDE_CONFIG_DIR`, а без неё
`~\.claude`. Одна строка, только токен:

```powershell
Set-Content -NoNewline -Encoding ascii "$HOME\.claude\usage-limits-token"          "sk-ant-oat01-..."   # головной
Set-Content -NoNewline -Encoding ascii "$HOME\.claude-accounts\pro\usage-limits-token" "sk-ant-oat01-..."   # другой
```

Файл подхватывается сразу, перезапуск не нужен.

**Переменная окружения — только для одного аккаунта.**
`CLAUDE_USAGE_LIMITS_CHECK_TOKEN` guard по-прежнему понимает, но **только у
аккаунта по умолчанию и только если файла нет**. Пользовательскую переменную
наследуют все процессы, в том числе второй аккаунт, — именно так оба аккаунта
однажды мерили лимиты одного. Если на машине больше одного аккаунта, переменную
удалите:

```powershell
[Environment]::SetEnvironmentVariable('CLAUDE_USAGE_LIMITS_CHECK_TOKEN', $null, 'User')
```

**Не используйте `CLAUDE_CODE_OAUTH_TOKEN`** — её читает сам Claude Code, и
глобальное значение сменит способ входа работающего приложения.

## 3. Подключить хуки и навык

Одна команда, для всех аккаунтов на машине; повторный запуск безопасен —
сделанное пропускается:

```powershell
& "<python>" "<guard>\install_user_hooks.py"
```

Пути в хуках и в разделе `CLAUDE.md` установщик берёт от расположения клона: хуки
запускают `<python>` этого клона (если его нет — тот Python, которым запущен
установщик). Для каждого каталога аккаунта (`~\.claude` и каждая папка
`~\.claude-accounts\<имя>` — другие аккаунты TaskDelegator, корень меняет
`TASK_DELEGATOR_ACCOUNTS_ROOT`; список — в начале скрипта, `CONFIG_DIRS`) он:

1. **добавляет хуки** в `settings.json` (если там уже есть свой блок `hooks`, не
   трогает его и говорит об этом — тогда сведите вручную, см. ниже);
2. **подключает навык `long-run`** junction-ссылкой
   `skills\long-run` → `<guard>\skills\long-run` (копия навыка одна, прав
   администратора не нужно);
3. **дописывает в `CLAUDE.md`** раздел «Бюджет использования» — правило
   «кончился бюджет — это пауза, а не конец».

Затем перезапустите Claude: хуки и навыки читаются при старте сессии.

### Что подключается

| Событие | Режим | Что делает |
|---|---|---|
| `UserPromptSubmit` | `prompt` | блок `Limits:` в контекст ассистента на каждом вашем сообщении |
| `PostToolUse` | `watch` | то же после вызова инструмента — только начиная с 90 %, не чаще раза в 10 мин |
| `Stop` | `stop -probe force` | итоговые цифры **вам** после каждого хода, свежий замер |

### Вручную

Блок для `settings.json` аккаунта (в `~\.claude\settings.json`,
`~\.claude-accounts\<имя>\settings.json` — одинаковый). Подставьте свои пути, через `/`:

```json
"hooks": {
  "UserPromptSubmit": [{"hooks": [{"type": "command", "timeout": 15,
    "command": "<python>",
    "args": ["<guard>/usage_guard.py", "-mode", "prompt"]}]}],
  "PostToolUse": [{"matcher": "*", "hooks": [{"type": "command", "timeout": 15,
    "command": "<python>",
    "args": ["<guard>/usage_guard.py", "-mode", "watch"]}]}],
  "Stop": [{"hooks": [{"type": "command", "timeout": 15,
    "command": "<python>",
    "args": ["<guard>/usage_guard.py", "-mode", "stop", "-probe", "force"]}]}]
}
```

Навык:

```powershell
New-Item -ItemType Junction "$HOME\.claude\skills\long-run" -Target "<guard>\skills\long-run"
```

### Жёсткий запрет (по желанию)

Режим `hook` для `PreToolUse` запрещает тратящие бюджет инструменты на 95 %.
С 2026-09-09 он **не подключён**: хватает предупреждений и протокола паузы. Если
нужен — добавьте `"PreToolUse"` с `"matcher": "*"` и `"-mode", "hook"`.
Осторожно: ошибка в этом хуке блокирует **все** инструменты сессии, включая те,
которыми его можно было бы исправить, — расцепить сможет только человек из
отдельного терминала. Перед подключением прогоните самотест.

### Отключить

Удалите блок `hooks` (или три записи guard'а) из `settings.json`, ссылку
`skills\long-run` (`Remove-Item` на junction удаляет только ссылку) и раздел
«Бюджет использования» из `CLAUDE.md`.

## 4. Проверить

```powershell
& "<python>" "<guard>\usage_guard.py" -mode probe     # прямой запрос к серверу — жив ли токен
& "<python>" "<guard>\usage_guard.py" -mode status    # полный отчёт
```

Ожидаемо для `probe`:

```
Limits:
5h: 14.0%, R: 2026-11-18 05:10:00
7d: 11.0%, R: 2026-11-22 05:00:00
(measured just now; server says 5h allowed, 7d allowed)
```

Чтобы проверить **другой** аккаунт, запустите с его каталогом:

```powershell
$env:CLAUDE_CONFIG_DIR = "$HOME\.claude-accounts\pro"; & "<python>" "<guard>\usage_guard.py" -mode probe; Remove-Item Env:CLAUDE_CONFIG_DIR
```

У разных аккаунтов цифры должны различаться. Одинаковые — значит, оба берут
один токен (см. [диагностику](#если-что-то-не-работает)).

В сессии Claude хук виден сразу: блок `Limits:` в контексте после вашего
сообщения и строка с цифрами после ответа.

## Использование

### Режимы

| `-mode` | Кто вызывает | Что делает |
|---|---|---|
| `status` | вы / ассистент | отчёт для человека: проценты, время сброса, темп, запас |
| `json` | скрипты | то же машиночитаемо |
| `probe` | вы | один запрос к серверу, всегда по сети — проверка токена |
| `prompt` | хук `UserPromptSubmit` | бюджет в контекст на каждом сообщении |
| `watch` | хук `PostToolUse` | то же, но только когда бюджет на исходе |
| `stop` | хук `Stop` | итог хода пользователю |
| `hook` | хук `PreToolUse` | запрет инструментов на пороге паузы (не подключён) |
| `wait` | навык `long-run` | ждёт сброса окна, печатает одну строку и выходит |

Ассистенту не нужно опрашивать бюджет: хуки сообщают его сами. `status` вручную
— только для планирования: сколько задачи влезет до сброса.

### Пороги

| Окно | Предупреждение | Пауза | Ключи |
|---|---|---|---|
| 5 часов | 90 % | 95 % | `-warn-pct`, `-pause-pct` |
| 7 дней | 95 % | 98 % | `-weekly-warn-pct`, `-weekly-pause-pct` |

Чтобы сменить порог для хука, добавьте ключ в его `args` в `settings.json`.

### Пауза и автопродолжение (навык `long-run`)

На паузе ассистент записывает чекпоинт в `.claude\tmp\long-run\CHECKPOINT-<сессия>.md`
текущего проекта, взводит фоновое ожидание (`-mode wait`, ничего не стоит), пишет
одну строку и останавливается. После сброса окна ожидание будит его, он
перепроверяет `status`, перечитывает чекпоинт и продолжает сам. Если упёрлось
**недельное** окно, ожидание не взводится — оно бы простояло сутки.

Отменить взведённое автопродолжение — сказать «стоп» / «останови». Без
токенов, если бюджета не хватает даже на разговор, — флаг-файлом:

```powershell
New-Item -ItemType File "$env:TEMP\claude-usage-guard-stop" -Force          # все диалоги, все аккаунты
New-Item -ItemType File "$env:TEMP\claude-usage-guard-stop-<сессия>" -Force # один диалог
```

Ожидание живёт в сессии: закрытие приложения его убивает, переживает только
чекпоинт. Подробности — `skills\long-run\SKILL.md`.

## Откуда цифры

1. **Сервер** (нужен токен). Каждый ответ `api.anthropic.com/v1/messages` несёт
   заголовки `anthropic-ratelimit-unified-*`: точную загрузку и **настоящее
   время сброса** обоих окон. Проба — один запрос к Haiku с `max_tokens: 1`,
   около 0,00007 % окна. Результат кэшируется на 20–90 с в зависимости от загрузки.
2. **Файл десктоп-приложения** `%APPDATA%\Claude\plan-usage-history.json` —
   запасной вариант, только для аккаунта по умолчанию (приложение пишет его для
   своего входа). Обновляется раз в 15 минут, время сброса оценивается.
3. **Стенограммы сессий** `<каталог аккаунта>\projects\**\*.jsonl` — оценка
   прироста с момента последнего замера.

Что у каждого аккаунта своё, а что общее:

| Что | Где | Чьё |
|---|---|---|
| токен | `<каталог аккаунта>\usage-limits-token` | свой |
| кэш пробы | `%TEMP%\claude-usage-guard-probe[-<хэш>].json` | свой |
| состояние `watch` | `%TEMP%\claude-usage-guard-state[-<хэш>].json` | свой |
| стенограммы | `<каталог аккаунта>\projects` | свои |
| флаг отмены | `%TEMP%\claude-usage-guard-stop` | **общий** намеренно |

`<хэш>` добавляется для всех аккаунтов, кроме аккаунта по умолчанию.

## Новая машина или новый аккаунт

- **Новая машина:** клонировать репозиторий в любую папку, запустить
  `python_setup.bat`, затем шаги 1–4. Навык `long-run` путей не содержит: он берёт их из
  раздела `CLAUDE.md`, который пишет установщик.
- **Перенос клона:** пути в уже записанных хуках и в разделе `CLAUDE.md` старые. Удалите
  блок `hooks` из `settings.json` каждого аккаунта, раздел «Бюджет использования» из его
  `CLAUDE.md` и ссылку `skills\long-run`, затем запустите установщик снова.
- **Новый аккаунт на этой машине:** добавить его каталог в `CONFIG_DIRS` в
  `install_user_hooks.py`, выпустить ему токен под его учёткой, положить в его
  каталог и запустить установщик ещё раз.

## Безопасность

- **Не вставляйте токен в чат с ассистентом** — он осядет в стенограмме.
- **Не коммитьте его** ни в один репозиторий.
- Файл токена хранит его открытым текстом в профиле пользователя Windows —
  тот же класс хранения, что и `setx`/реестр.
- Токен даёт только `user:inference`; отозвать его можно в настройках аккаунта
  Anthropic.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `claude : имя не распознано` | CLI не в PATH — нужен полный путь, шаг 1 |
| Путь через `%APPDATA%` не находится | виртуализация MSIX — путь под `LocalCache`, шаг 1 |
| `probe unavailable: no ...usage-limits-token` | нет файла токена у этого аккаунта; путь — в сообщении. Шаг 2 |
| Два аккаунта показывают одинаковые цифры | оба берут один токен: общая переменная или токен выпущен не той учёткой. Шаги 1–2 |
| `probe failed (token from ...)` | сеть, отозванный токен или сменившийся эндпоинт; guard сам перейдёт на запасные источники |
| `403 ... scope requirement user:profile` | это запрос к `api/oauth/usage` — он недоступен и не нужен, guard берёт данные из заголовков `v1/messages` |
| В `Limits` пометка `local files, not measured` | проба не проходит; причина — после дефиса или в `-mode probe` |
| Нет блока `Limits` в сессии | Claude не перезапускали после установки; или нет блока `hooks` в `settings.json` этого аккаунта; или нет Python по пути из хука |
| Блок `Limits` приходит дважды | у проекта остались свои хуки guard'а в `.claude\settings.json` — удалить их там |
| Хук падает с `badly formed help string` | `%` в тексте `help` у argparse: Python 3.14+ проверяет его сразу — удвоить `%` |

## После правок в `usage_guard.py`

```powershell
& "<python>" "<guard>\verify_usage_guard.py"
```

Восемь сценариев оценки и восемь проверок разделения аккаунтов — все должны
пройти. Самотест герметичен: токен из окружения и каталог аккаунта он подменяет и
в сеть не ходит.
